# Session Log: Fix HR_avg_0 / HR_incr in 2035 Conversion

**Date:** 2026-04-10
**Branch:** idaes_coal2
**Goal:** Fix corrupted HR_avg_0 values that prevent NUC/COAL dispatch in 2035 Prescient simulation

## Problem

The 2035 Prescient simulation showed zero NUC/COAL dispatch despite correct marginal costs ($7.38/MWh NUC, $18.94/MWh COAL). Root cause: `demo_processing_prescient.ipynb` computed HR_avg_0 using a startup cost formula (`Csu × PMax / FP`) instead of an actual heat rate. Egret parser uses HR_avg_0 to compute PMin fuel cost, giving NUC **$1.2M/hr at PMin** — making it impossible to commit.

## Changes Made

### 1. Cell 1: SCENARIO path update
- Changed `SCENARIO` to `retirement_allowed_no_extreme_half_load_local`
- Decoupled `SOLUTION_DIR` (GTEP solution stays at non-`_local` dev path)

### 2. Cell 3: HR recomputation from C0/C1/C2 cost curves
- Added `recompute_hr_from_cost_curve()` function that derives proper BTU/kWh heat rates from quadratic cost coefficients: `C(P) = C0 + C1*P + C2*P^2`
- HR_avg_0 = average heat rate at PMin = `C(PMin) / (FP × PMin) × 1000`
- HR_incr_i = incremental heat rate per segment = `delta_cost / (FP × delta_MW) × 1000`
- Applied to all thermal generators with valid C0/C1/C2 columns
- Inserted before fuel price back-calculation (so corrected HR_incr_1 feeds into FP calc)
- Added diagnostic prints for HR ranges and PMin cost sanity check

### 3. Copied run/submit scripts
- `run_coal_prescient_2035.py` → `_local/`
- `submit_job_2035.py` → `_local/`
